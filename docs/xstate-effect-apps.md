# Apps delivery and render lifetimes

B12 keeps app definitions, saved checkbox/form/web values, immutable interaction receipts and event identity in the existing Apps ledger. `delivery.machine.ts` owns each event's pending → admitted/cancelled/exhausted progression. `pump.machine.ts` owns one local delivery pass. `render.machine.ts` owns preparing → executing → committing → settled for one request. All local actors use the official Effect integration and request/pass scopes; no new task engine or journal exists.

## Durable acceptance and handoff

The HTTP adapter checks an exact saved receipt before scheduling. Reuse with different immutable input fails. A new interaction prearms `AppEventRunner.armDiscovery()` and passes its actual retained deadline through remote rendering to the ledger. The interaction transaction checks that deadline before writing saved state, event and receipt together. A response lost after commit can be replayed without a functioning scheduler or another sandbox execution.

Apps-to-Conversations admission stays inside the same `Sqlite.transaction` and exact `transactionGroup`. The event's stored turn ID becomes the Conversations operation ID; Conversations returns that same ID or the transaction fails. Apps writes its admitted machine state in that transaction. The Conversations discovery lease is separately prearmed before this handoff. Pi execution, checkpoint/recovery and provider side effects remain Conversations/Pi responsibilities. Neither a queued Apps event nor a Conversations receipt proves completed model work.

Before handing off, the ledger rereads bot activity, app archival and the current published version. Changed authority cancels the pending event while retaining its saved state and immutable interaction receipt. The production configuration boundary commits an accepted bot archive, pending-event cancellation and an increment of each existing app revision in the same SQLite transaction. Both ledgers must share that exact database coordinator. Cancellation or revision-write failure rolls the archive back. Replayed and older profiles do not advance app revisions or cancel restored work; the pending-delivery guard also rechecks bot activity inside its transaction. Access remains in the worker's existing family admission and authenticated request composition.

## Storage and compatibility

`generated_app_events.record` now includes a versioned lifecycle record: application schema/workflow versions, state, revision, failed-admission count, next eligible time and a finite recovery deadline. No table, column, app identity or interaction receipt changes. The existing `queued` column is a pending index, derived from machine state; it is not another controller.

Legacy pending and queued records convert deterministically to pending and admitted machine records while preserving event ID, turn ID, text, published version and creation time. The next committed transition persists that conversion atomically. Unknown versions, malformed states and inconsistent delivery projections fail rather than resetting an event. Status reads terminalize expired pending controls, so a later successful storage read exposes recovery exhaustion even when the earlier terminal write failed.

The admitted public projection remains `queued`. Cancelled/exhausted events carry an actionable delivery message. Saved app content is unchanged by delivery terminalization. A new interaction after resolving the model/storage issue uses a new operation ID; replay of the old ID continues returning its original immutable saved result.

## Retry and retained discovery

Missing-model and full-queue business deferrals are persisted, FIFO, capped at five failed admissions, and use exponential delays capped at five minutes. Every pending event also has a 15-minute deadline derived from its original acceptance time; restart does not renew it. An exhausted event cannot admit or resurrect.

The existing Lifecycle capability and job identities remain `app-events` / `app-events:pump`. The job payload is the only durable discovery lease. It is versioned and token-fenced. A pass retains the persisted 60-second admission lease even after an empty scan, including when an already-armed render commits after the scan and its immediate wake is lost.

An active dispatch, including the SDK retry gap, cannot be renewed by an admission doorbell. `armDiscovery()` returns its actual persisted deadline only when at least 30 seconds remain; otherwise it rejects before acceptance. This short busy rejection is intentional. No clock-derived deadline is represented as persisted intent. A post-commit wake only rearms an active job, preserving the SDK retry budget.

Lifecycle has three SDK execution attempts with 100 ms base / 1,000 ms maximum delay. Exhaustion persists a spent lease before trying terminal writes. That lease may only terminalize late accepted interactions until its deadline; it cannot execute another pump. A late completion or failure cannot delete or exhaust a newer token, and stale armed callbacks reread the persisted state when the token is already spent. If terminal persistence remains unavailable, the event's existing deadline survives. Reconciliation and fresh admission with no retained job terminalize orphan controls before another epoch can be granted. If the spent-marker write failed, the original local dispatch lease also fences new admission until its actual deadline; an in-flight render cannot cross into a fresh epoch. A cold process has no surviving local renders. Exact saved receipt replay needs no new scheduling budget.

## Local render resources

One Effect semaphore permits one sandbox request per bot. A request-scoped actor owns preparation, execution and commit; acquire/use/release holds the permit until native cleanup has actually settled. A 15-second shared request deadline aborts the resource before joining cleanup. If foreign code ignores abort, cleanup can exceed the deadline; another render cannot reuse its permit while that native work remains unresolved.

Archive invalidation and HTTP cancellation abort the owned resource and send the machine a cancellation event. Local archive invalidation rereads the bot configuration and performs its synchronous abort while holding the shared database coordinator, outside the SQL transaction. A delayed callback skips invalidation after restore; restore cannot overtake an archived authority read and expose newly authorized work to that callback. Native cleanup remains outside this coordinated read and is joined by the render scope. The abort signal is also checked immediately before/after native execution and before commit: asynchronous mailbox ordering alone does not fence same-turn native settlement. Bot activity and app revision are rechecked at preview completion; interactions recheck the current published version and expected revision in their atomic commit. The archive transaction advances that existing app revision even if restore overtakes local invalidation, so a held prearchive preview or interaction cannot complete after the bot is restored. This revision change is an authority fence: app content, saved values, published versions and immutable operation receipts remain unchanged. An exact receipt replay still returns its original saved result. Draft previews remain supported.

Timeout and ordinary app rejection retain saved state. Defects and compound teardown failures stay fatal rather than becoming ordinary conflicts. Public preview responses do not commit sandbox-returned state. Durable interaction receipts remain the authority for duplicate actions.

## Evidence and limits

Focused tests are `apps.test.ts`, `web-apps.test.ts`, `pi-apps.test.tsx`, `app-pump.test.ts`, `app-delivery-machine.test.ts`, `app-render-machine.test.ts`, `app-lifecycle.test.ts` and `apps-configuration.test.ts`. They cover storage rollback across both ledger owners, wrong transaction-group refusal, exact receipt replay, identity/content conflict, legacy/future versions, fenced revisions, finite business retries, archive/version cancellation, archived render refusal, synchronous archive/restore completion, HTTP abort, bounded native cleanup, defects, and recovery without state/receipt mutation.

Configuration tests use the real synchronization machine with restore committed before its first authority read, and hold native render completion across that same archive/restore sequence without manually invalidating the renderer. The retained production-helper tests also hold local invalidation until after restore and hold its authority read while restore is waiting, proving that fresh renders survive stale callbacks and that the coordinated read cannot be overtaken. Real SQLite triggers prove that pending-event and app-revision write failures roll configuration back; a split-transaction negative control preserves a prearchive pending event and demonstrates the original gap. These tests prove local transaction and revision boundaries; they do not claim that interrupting native sandbox work undoes remote effects.

Lifecycle race tests hold an empty scan, prearm during that active pass, let the scan finish, then commit with its immediate wake lost. They also cover the near-expiry negative control, spent-lease late commits, terminal-write outage, stale callbacks and absent-job orphan terminalization. These in-process fixtures do not alone prove Cloudflare alarm behavior; the separate native process-restart/no-object-request result is recorded below.

The worker's App prearm error mapping now maps only typed failures within the complete Effect Cause. A prearm failure combined with a teardown defect or interruption remains fatal instead of becoming an ordinary HTTP rejection. The [30 actual Agent HTTP tests](evidence/xstate-effect/b11-b12-2026-10-23/b12-agent-http.log.txt) passed after this repair. The [independent helper review](evidence/xstate-effect/b11-b12-2026-10-23/b12-archive-helper-review.log.txt) passed eleven cases in a scratch copy, including direct calls to the production `invalidateArchivedApps` helper. Its [unguarded-callback negative control](evidence/xstate-effect/b11-b12-2026-10-23/b12-stale-invalidation-negative.log.txt) fails when an old archive callback aborts a fresh restored render. The retained repository configuration tests also pass in the final unit gate.
