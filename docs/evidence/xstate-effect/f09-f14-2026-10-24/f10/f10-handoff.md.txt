## Invariants and boundaries

1. The editor machine owns save admission, immutable fields/revision, acknowledgement, read reconciliation and close. A successful earlier save cannot close or overwrite later edits. A received create profile changes subsequent explicit saves to update. Known client rejection allows corrected fields; uncertain transport outcomes retain the exact original fields and entity identity for an explicit retry. No automatic write retry occurs.
2. Received save/archive acknowledgement is separate from catalog refresh. Failed reconciliation only retries the read. Archive requires confirmation, restore remains explicit, and in-flight commands cannot be replaced/dismissed. Capacity errors and saved agent work remain visible.
3. The catalog actor serializes reads and coalesces queued refreshes, suppressing the superseded result. Its existing initial-loading-only projection is preserved. Failed refresh retains prior data and rejects waiting callers. The old reducer is deleted rather than retained as a second owner.
4. Status observations are periodic read-only work every 30 seconds while visible and membership is nonempty. Native reads never overlap; membership changes during a read require a fresh joined observation before publishing. Effect owns the timer and visibility listener. Live data is fenced by owner and selected agent.
5. The workspace guard owns initial-ready retention and navigation-block notice/admission from current safety facts. Router remains route/search authority. Explicit editor dismissal and acknowledged archive routing retain their existing authorized Router calls. Native blocked navigation observes an awaited machine reply, never an assumed synchronous mailbox update.
6. Workbench presence retains panel/search until the corresponding exit acknowledgement. Revision fencing rejects a stale close after reopening, while Base UI owns actual animations. The location helper is pure URL projection/canonicalization and native Router calls; WorkbenchPanel is a native Base UI adapter. Neither needs a competing application navigation/animation engine.
7. Every actor has an owned Effect scope. Native request promises remain joined after abort. Owner retirement revokes future callbacks immediately; late successful saves cannot reconcile/close a replacement view. Structured checked failures and original defects survive late cleanup through the canonical fatal-reason promotion, without nesting an entire Cause inside Die.
8. Selection values, child-owner pending projections, view caches, native SDK state and URL data retain their native/pure owners. Existing local/session storage keys and formats are unchanged; no reset, migration or new browser persistence was introduced. The existing session/agent React keys preserve draft ownership. The parent retains its reserved MemoryWorkbench prop bridge and shared final documentation.
