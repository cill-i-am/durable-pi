## Contract and ownership

`query.machine.ts` is the official Effect-backed owner for initial/manual read admission, reading, waiting, hidden observation, settled/manual history and fatal failure. It retains one current native read. Explicit refresh invalidations coalesce to one successor for polling; duplicate pagination requests are ignored while occupied. The owner joins each read's scope before admitting its result or starting a successor. Visibility events update observation permission; hidden automatic polling pauses and becoming visible resumes. Terminal saved conversations settle without more polling. Explicit refresh remains possible.

`use-activity-query.ts` owns an Effect scope per semantic query key and enabled state. Each owner captures its read capability once. Both publication and new dispatch check current identity/enablement before React effects can publish a prior view. Unmount revokes local observation and forks a scope-close join; native cleanup remains owned until it settles and a compound cleanup failure is logged by the owning boundary. It does not stop remote work.

`query-owner.ts` supplies the native boundary. `activityQueryRequest(read(signal))` aborts and joins native settlement, retains structured late Fail+Die and Fail+Interrupt (including original reason annotations) and deduplicates reasons already observed. Effect finalizers use the repository `fatalCause` representation: checked Fail reasons are retained as complete defect payloads because finalizers cannot have checked errors. `activityJsonRequest(agentId,path,signal,body?)` retains the existing ApiError status/message/code contract, joins unread response-body cancellation (including 401), combines cleanup failures with the original error, and preserves structured JSON-read Causes. The companion control owner reuses these HTTP/resource mechanics, while its own machine decides command progression.

`usePlans` reads list/detail/access concurrently inside one observation. The first native failure aborts sibling requests; all sibling promises settle before that observation releases ownership. Plan detail, pending approval filtering, page offsets and immutable plan/run history projections stay unchanged. A wrong plan/run ID returned by a history endpoint cannot be published under a different selected identity. Plan history uses the unchanged `historyPage` projection; run history returns the same latest/earlier views.

Existing cadences remain: plans and model activity 2.5s; activity list 5s/latest or15s/cursor; saved record3s; history only explicit requests. The shared companion surfaces choose their existing intervals. Ordinary transport/decoded read failures keep periodic reconnect behavior while visible, including beyond five consecutive failures. There is no new five-failure cutoff and no automatic business-action replay. Fatal compound failures retain an error until an explicit refresh; no command or Pi authority is created by query retry.

These are volatile query-resource owners. Existing query DTOs, `historyPage`, `RunEventView`, elapsed/usage projections and route selection remain pure data/UI inputs; no durable snapshot/version/journal is introduced. Remount performs a fresh GET observation rather than restoring unfinished external work. Backend domain rows, receipts and native Pi resources remain authoritative.
