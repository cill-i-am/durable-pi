## Invariants and implementation

- `workspace-command.machine.ts` alone admits opening, closing and captured action/agent commands. Closing ignores subsequent choices. Its matching revision completion authorizes at most one dispatch; reopening replaces the revision and revokes the old command. Current lock is checked both at admission and the capability dispatch boundary. Lock invalidates the pending command; unlocking does not automatically reopen or replay it. Exact current-agent selection still invokes the existing parent selection callback, preserving navigation back to that agent's conversation.
- `use-workspace-command.ts` gives the actor an Effect scope, owns the keyboard listener, fences retired dispatch, and exposes only snapshot projections and events. No new animation timer or navigation wrapper. Native focus return keeps the original trigger/fallback behavior; selecting a command retains the existing skipped focus return for the next view. The superseded searchOpen setter, afterSearch ref and skipSearchFocusReturn ref control path are removed.
- `workspace-link-retry.machine.ts` owns ready -> invalidating -> resetting -> ready. Only an explicit retry can start work; duplicate retries while occupied are ignored. The error identity is captured with that attempt. Error replacement keeps the held native request occupied, and its acknowledgement cannot reset the replacement error. An ordinary invalidation failure returns to ready for an explicit retry.
- `use-workspace-link-retry.ts` keeps one actor for the mounted recovery view. It joins actual Router invalidation settlement on scope close and fences reset on unmount/current error identity. It observes and retains mixed annotated cleanup Causes despite official actor shutdown materializing child Exits. Expected interruption-only shutdown stays local; no Die(Cause) nesting. Router owns its native cancellation semantics; the host does not invent a cancellation API. The retrying React progression setter and imperative retry function are removed.
- Local state is ephemeral. Existing browser data and durable identities remain unchanged; no migration or reset is needed.
