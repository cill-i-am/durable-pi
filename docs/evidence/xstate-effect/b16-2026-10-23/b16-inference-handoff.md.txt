## Contract and implementation

The scoped official Effect request actor owns checking, acquisition, each native read, bounded publication, closing and completed progression. The owner actor serializes admission with shutdown and tracks native occupancy separately from refused-request completion. Sixteen provider slots remain the maximum; declined completions are joined before shutdown returns without taking provider slots. A distinct owned request scope stays open until queued, accepted and refused work drains, then closes after the owner actor. Both explicit shutdown and direct runtime disposal are covered.

The ten-minute request deadline is anchored to admission time; mailbox delay cannot extend it. It continues across joined cleanup. Existing 128-pending-event and 16 MiB provider-body limits remain. Overflow retains precedence over timeout while native release joins. No local cancellation releases occupancy before native callbacks, iterator return, body cancellation/release and the final completion callback settle.

A synchronous official machine reserves each request object once before its SDK facade queues admission. A separate synchronous consumer machine admits either the iterator or result-only drain; a competing consumer fails without aborting the admitted consumer. These are immediate facade decisions; all request and owner work runs through `createEffectActor` in explicit Effect scopes. Mutable native SDK event/partial objects stay outside snapshots because XState freezes snapshot data; only progression classifications enter the actor.

Cleanup retains every original Effect Cause reason using the repository's fatal mapping (a checked Fail remains a complete Fail reason carried as a Die payload). Iterator/body cleanup no longer wraps an entire Cause as one opaque Die. Existing final authority/catalog/credential hooks in `models-pi.ts` remain at their original consequential dispatch boundary. Diagnostic observation expiry remains in the separate upstream owner and cannot abort this inference owner.
