## Behavior
Official XState/Effect machines decide Summary discovery, dispatch and scheduler recovery. Domain claims remain the sole per-summary authority. The native scope is retained with `ctx.waitUntil`, interrupted on disposal and joined before runtime/storage shutdown; complete Causes survive cleanup failures. Failed joined passes retry exact receipt settlement and idempotent handoffs, without another provider scan. Cold restore is called only from actual onStart; warm facades/status/reconcile never restore claims.

The literal legacy pump ID is `memory-compactor:pump`, capability `memory-compactor`; discovery uses `memory-compactor:discovery`. Versioned controller diagnostic uses Lifecycle storage key `memory-compactor:failure`. `armDiscovery()` returns an actual finite 60-second deadline; `discoveryCurrent(deadline)` verifies the retained job synchronously inside the import/journal SQL transaction. Exhaustion blocks ordinary wakes/admission and exposes `{epoch,failedAt,message}`. Exact `armRecovery(epoch)` then `retryRecovery(epoch,deadline)` grants recovery; stale epochs or expired/replaced leases cannot clear diagnosis. A held producer retains its original token during discovery exhaustion/recovery, so no replacement native producer starts before join.

Worker now wires SummaryRunner and BackupRunner instead of MaintenanceRunner subclasses; actual startup restores their domain state once. Import and Conversation journal publication prearm both owners and validate actual current leases after shared SQL acquisition. Application receipt replay repeats notify, backup wake and active conversation wake even after publication already committed.

Authenticated Memory routes: `POST memory/retry_compaction {epoch}`, `POST memory/backup/retry {attemptId,target}`, `POST memory/backup/recover {epoch}`. Successful exact admission is 202; stale/expired/live-owner conflicts are 409. Report projects optional `memory.compactionRecovery` and `memory.backup.schedulerRecovery`; domain owns `memory.backup.recovery`. UI scheduler extension is owned separately by mailbox_recovery_ui.
