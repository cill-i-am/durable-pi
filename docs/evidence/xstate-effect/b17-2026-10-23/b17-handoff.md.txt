## Limits / compatibility

Receipt is bounded observed family authority, not cross-database atomicity. Already-started native work may complete after revocation; stale continuations are rejected and no automatic tool replay is introduced. Registered same-revision replay does not prove SDK registration provenance; interrupted registration may require explicit reconnect using the current revision. SDK OAuth cleanup can fail; generation namespace prevents stale pending state/verifier reuse but makes no credential-deletion guarantee. Legacy unversioned pending OAuth is rejected and requires fresh authorization via reconnect; existing credentials and records are retained. Tests use real local SQLite and installed SDK methods with synthetic transports, not live MCP providers, real auth mutation, or native no-request alarm proof.
