# Effect-native refactor

The refactor preserves persisted formats, native Pi replay, authorization, resource identities and the single Lifecycle alarm owner. Domain decisions stay direct; application operations use Effect capabilities; adapters own SQL, SDKs and runtime bridges. A synchronous storage transaction is an intentional port, never an invitation to run a separate Effect runtime inside a transaction.

## Evidence and review basis

- [OpenCode](https://github.com/anomalyco/opencode/tree/3a69bae8459b1aa9b122456a55d9535b23125f33): narrow execution/store contracts, scoped coordination and transport error mapping. Durable recovery depends on committed claims, not finalizers.

September ended at RC 118; stable v4 shipped October 1. In-memory `Effect.tx` is not durable SQL.

## Stages

1. **Dependency and consistency contracts** — completed. Resolve import aliases and type imports when protecting domain/application modules. Document and test atomic admission, rollback, replay and receipt limits. Extend protection as each context moves.
2. **Routines and webhooks** — completed. Move decisions from SQLite; provide Effect operations and explicit synchronous transaction ports. HTTP and Pi tools use the same service. Map semantic webhook failures at HTTP only.
3. **Access, Apps, Skills, Terminal and Communication** — completed. Replace concrete adapter dependencies with owned capabilities; typed operation failures and scoped coordination. Normalize receipts at their owning boundary.
4. **Conversation lifecycle** — completed. Conversation admission/retry/stop, pump, recovery, journal, snapshots and streams use owned capabilities; Pi and Lifecycle remain native adapters; instance services share one scoped graph.
5. **Remaining contexts and persistence/host policy** — completed. Memory, Agents, Objects, Planning, Workspace, Browser, Execution, Inference, foreground/background Delegation and Activity have owned application capabilities and native adapters. Backup, provider, transfer, authentication, gateway and remaining ingress/host ownership are implemented and verified. Historical codecs, durable recovery and synchronous SQLite/Pi authority are retained.
6. **Native SQL and HttpApi pilots, final integration** — completed. Native driver conformance and Pi read interoperability are verified; the catalog GET uses a retained HttpApi router. The complete requirement matrix and final dependency/resource/error audit are recorded below, with findings fixed and local gates passing. Synchronous aggregate transaction ports and Pi's journal remain authoritative.

Each stage review records policy ownership, dependency direction, error semantics, lifetime/cancellation, durable guarantees, reference/skill alignment, checks run and remaining gaps. Passing a stage does not imply the whole refactor is complete.

| Pattern / invariant                       | Decision and completion evidence                                                                                                                                                                                                                                                                                                                                                                                      |
| ----------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

Core rules cover aliases, re-exports, literal dynamic and type imports, runner aliases and platform dependencies; backend runtime cycles are lint errors.    |
| Typed failures and transport boundaries   | Adopted finite Schema-backed expected errors and exhaustive typed tag handlers. Owned native/RPC values are decoded rather than relying on class prototypes. Defects, interruption and compound Causes survive local bridges and explicit native outcome protocols; public errors redact private diagnostics. This resolves the connection HTTP review comment and applies the same criterion throughout the backend. |

Held-resource and late-failure laws cover shutdown ordering.                 |

### Verification boundaries

These are local implementation and verification results. Workerd exercises real DO SQLite, Pi, Lifecycle, native RPC, Worker Loader and WebSockets. Unit integration exercises real Better Auth with the existing Node SQLite migrations. Provider/MCP/container/R2 responses and session identity in the workerd fixture are synthetic; this does not prove live D1/auth/provider/OAuth/Sandbox/R2 behavior or a deployed system.

Native RPC still cannot remotely cancel an admitted method. Where a display deadline returns early, the Worker owns the remaining read and its result cannot mutate the cancelled aggregation. Other admitted foreign work is joined; a noncooperative SDK or cleanup can extend cancellation beyond a nominal deadline. Graceful finalizers do not protect abrupt isolate death: committed claims, replay identities, uncertain-outcome fences and restart reconciliation do. A foreign serializer that already erased a Cause cannot be reversed; owned RPC paths use explicit outcome envelopes. HTTP and finite typed-error projection are deliberate privacy boundaries, not evidence that an external effect rolled back.
