## Compatibility and verification boundaries

Auth's default callable has Better Auth's module lifetime; explicit consumers use `makeSessionFetch` in their own Effect scope. Catalogue storage, Terminal capacity tokens and migration markers keep their prior representations. Restoration rejects incompatible facts rather than clearing them. Native container and bucket capabilities in the new workerd probe are controlled synthetic operations; its SQL, key/value storage, transactions, streams and runtime are real. No production migration, provider delivery or deployment was performed.

The original independent Terminal and Coordination freezes remain historical evidence. The Coordination startup correction is an additional integration change; its eight-case independent held-cleanup probe passes unchanged after the correction. A parent-runner control passed the entire native Communication suite while the first composition hung during Coordination startup. Private tracing and scheduler experiments were diagnostics; only lazy scoped construction and direct Effect restoration were applied.

Local verification passed 3,703 tests in 329 files with two test workers, the website and all seven Worker builds, all 15 native suites, 246 browser journeys, 29 mounted-component cases, passkeys, two-build upgrade recovery, both container builds and static checks. The final shutdown correction is verified separately through the full native Communication/PersonalAgent suite and affected host tests. [Historical and composed evidence](evidence/xstate-effect/host-census-2026-10-24/README.md) retains exact source checkpoints, including an earlier unchanged Memory test timeout under overlapping verification and its unchanged-deadline passing reruns. Publication and hosted CI remain open.

## Further census findings

The full source rescan also found local callback ownership still expressed in mutable adapter fields in Conversation, Communication, Workspace, Routine and App runners. Memory Summary and Backup have explicit durable/dispatch machines, but their local activation/closed admission remains adapter-owned. These are remaining application lifecycle work under the same standard. Existing row-level durable proof stays valid for its recorded scope; repository-wide completion remains open until these host boundaries are migrated and verified.

Byte-reader/pipe release guards, native socket ready-state checks, copy feedback timers, attachment readiness projections and retained SDK/resource handles are mechanisms or projections. They do not acquire an additional business retry/admission authority. The census distinguishes those responsibilities from the mutable admission gates above.
