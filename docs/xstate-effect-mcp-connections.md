# MCP connection ownership

**Release status — 25 October 2026:** the refactor is [merged, deployed and verified](xstate-effect-release.md). The checkpoints below retain their original source and test scope; pre-merge delivery status is historical.

B17 invariants, implementation and falsifiable probes.

1. The existing connection row is the only activation authority. Its ID, normalized URL, active flag and monotonically increasing revision survive restoration; MCP SDK registration/authentication state is a projection, not another writable application authority. Exact command replay retains the same revision; conflicting/stale commands fail.
2. A connection command has explicit admission, native removal/registration/connection/discovery or callback states. Each consequential continuation rechecks the exact connection generation and current host authority after awaited work. Callback results cannot establish a generation other than the one that issued the pending OAuth state, including when the callback first arrives after reconnect.
3. Disconnect commits inactive before SDK removal. A failed or interrupted removal leaves the row inactive and retryable using the same command identity; it cannot authorize tools.
4. The host machine owns admission and draining independently from each command. Closing rejects new and queued mutation work, joins already-started native cleanup, and settles the SDK before releasing its scope. Caller cancellation/deadline cannot release the mutation permit before native settlement.
5. Scope closure preserves complete late failure Causes. Application machines do not reimplement MCP protocol, OAuth, token refresh or remote exactly-once execution.
6. No automatic business retry is added. Existing bounded native transports and 60-second mutation deadline remain. Restoring/replaying an active row may finish the existing registration/connect intent with its ID; external tool calls are never replayed.

Probes: actual SQLite callback held across disconnect/reconnect; host shutdown during registration with a queued mutation; disconnect write/remove failure; activation committed before native connect then fresh service replay; compatible/malformed/future machine state; catalog/selection generation rejection; cancellation and late compound Cause; meaningful removal of the callback generation guard must fail.

## Implemented ownership

`connection.machine.ts` reconstructs activation from the existing `access_connections` row and decides exact-revision activation/disconnection. `ConnectionStore.change` runs that decision in its existing shared SQLite transaction. Compatible rows keep their ID, name, normalized URL, revision and active flag. Exact replay returns the original record, avoiding a second write. There is no additional snapshot or migration. The version-one machine envelope validates explicit reconstruction/serialized inputs; the existing SQLite schema has no persisted workflow-version column. Future envelope versions and malformed envelope data are rejected rather than reset.

`connection-command.machine.ts` owns admission, inspection, removal, registration, connection, discovery, authorization acceptance and establishment. Connect and reconnect replay retain the existing SDK registration behavior. Disconnect persists inactive before invoking removal. A callback captures the active connection generations before entering SDK callback work. The native adapter verifies the current provider's pending state before calling the SDK handler, then returns the verified connection ID and issuing revision. Acceptance requires both to match a captured generation before establishment. This preflight is necessary because the installed SDK treats invalid state as success when a connection is already connected or ready. A disconnected or replaced generation cannot exchange an old authorization code or establish the newer connection.

`connection-host.machine.ts` owns open admission, active operation tickets, draining, SDK settlement and closure. The owning Layer creates its Effect actor in a detached scope and explicitly closes it after all operation tickets are released. A queued mutation rechecks host/current family authority after acquiring its semaphore. Each command runs its own scoped Effect actor; interruption joins its invoked native work before the ticket and mutation permit are released. A host drain stops later consequential SDK stages while allowing already-accepted inactive removal cleanup. Late defects and compound Causes remain available through `disposeEffect`, the same API used by the production worker. The convenience `ManagedRuntime.dispose()` Promise squashes errors and is not the complete-Cause evidence boundary.

The required `authorize` capability returns a fresh family admission receipt. It binds the existing family generation actor's exact epoch and ready state to a ten-second Effect-clock deadline. The actor increments its epoch before asynchronous revocation cleanup, immediately invalidating previously issued receipts. Receipt creation retries fresh admission if the epoch changes while admission is awaited. Connection activation writes validate the synchronous receipt after acquiring the existing SQLite coordinator; no directory lookup or actor mailbox work enters that transaction. Native stage guards read the exact connection generation, acquire fresh family authority, then reread the generation and validate the receipt after that final read. Both delayed storage and delayed authorization are covered. The callback adapter also checks the receipt after its awaited state preflight. This is bounded observed authority, not a cross-database atomic transaction with the family directory.

SDK functions remain the protocol and OAuth owners. `ConnectionOAuthProvider` captures its initial connection revision once; repeated SDK assignment of the same server ID cannot refresh it. Existing SDK pending-state and PKCE key families gain a revision namespace. The public nonce/server-ID state format, tokens, client metadata and discovery storage keys stay unchanged. The SDK still creates and validates one-use state, binds PKCE, exchanges codes and refreshes tokens. State and verifier keys left behind when SDK cleanup fails cannot be read by a newer connection generation. Legacy unversioned pending authorizations are rejected; the existing explicit reconnect starts fresh authorization. Credentials and connection rows are preserved. No transport object, credential, callback code or token is placed in a machine snapshot.

## Recovery and limits

There is no new automatic application retry or alarm owner. A connection row committed before registration remains available for an explicit replay with the original ID. Existing registered-state replay keeps any existing SDK registration intact; it does not prove that registration belongs to the newly committed revision. An interrupted/uncertain partial registration therefore may require explicit reconnect using the current revision, which advances the connection revision and removes the prior SDK registration before establishing another. This migration does not claim that registration or an OAuth exchange is externally exactly once. A native action already started before revocation may complete; the application rejects its stale continuation and tools still require current authority.

The existing 60-second mutation deadline remains a bounded transport deadline. Timeout and caller cancellation join native settlement. The installed MCP transport configuration remains one attempt, no automatic connection retries, no automatic scope escalation, and bounded discovery/tool timeouts. A failed disconnect removal leaves the authoritative row inactive; retrying the same revision retries removal without granting active authority.

## Evidence

The initial actual-SQLite callback race failed: an old held callback followed by disconnect/reconnect returned success and established the new generation. The corrected production service rejects that result and leaves revision three intact. The separate disconnect-only case also rejects establishment.

`tests/connection-lifecycle.test.ts` adds held register/connect/discover checks for both generation changes and family revocation; shutdown during registration with a queued mutation; full late cleanup Cause preservation; compatible/future/malformed reconstruction; pre-connect activation replay with the original identity; and disconnect replay under a trigger that rejects any second write. Existing `connections`, `mcp-oauth`, `mcp-failures` and `connection-http` tests retain catalog identity, selection revision, OAuth refresh/PKCE, native cleanup, deadline and HTTP error-sanitization coverage.

Independent review added production-boundary regressions for revocation behind a ledger read (including remote tool dispatch), revocation/expiry behind the actual SQLite coordinator, and stale callbacks arriving after reconnect into authenticating, connected and ready SDK states. The callback probes exercise installed SDK methods with synthetic transports and preserved OAuth storage after cleanup failure. Family tests verify invalidation before held revocation cleanup, expiry using Effect TestClock, initial legacy conversion and host disposal.

Two initial temporary source mutations failed at the intended assertions: replacing the callback's captured generation with a fresh row let the old callback establish the new generation; removing final stage authority checks let a revoked registration continue. Production source was restored after each mutation. These tests use real local SQLite and synthetic native capabilities; they are not live MCP-provider, real OAuth authorization, or no-request alarm/restart proofs.

Final focused validation: 133 tests across connection lifecycle, existing connection/HTTP/OAuth behavior, family admission/model/routine authority and agent HTTP boundaries; full TypeScript and scoped lint passed. Final immutable-source negative controls use test-only transform mutations: removing the in-transaction authority guard must commit a forbidden row, and removing the pending-state revision namespace must accept old state. Neither control changes production source. Exact hashes and independent review evidence are recorded separately by the integration owner.
