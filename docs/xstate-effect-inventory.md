Baseline: `696aca98000a6e82a9cb202acc18f92f2c8e987e` (initial discovery at `6ce50c15ee9af99fbe7e0c09f3e064ad0b81e1b1`, refreshed after #198). Status: **open**. Canonical rules: [XState Effect](decisions/xstate-effect-state-machines.md). Tracking owner: [BUILD.md](../BUILD.md#xstate-effect-lifecycle-refactor).

All application-owned lifecycles meeting the applicability definition must be explicit XState machines through the official `@xstate/effect` integration. Effect or pure functions implement work; Pi remains the durable execution engine where required. Every lifecycle has one authoritative owner, explicit recovery semantics and executable behavioral tests. Superseded handwritten control paths are removed.

## Discovery and completion rules

Discovery used `git ls-files src tests`, status/state/phase writes in schemas, `useState`/`useEffect`, retry/cancellation/timer searches, and callers/implementations in the paths below. Searches discover candidates; responsibility and control flow determine classification. No production XState imports existed at the baseline. The two conformance fixtures were the only implementations established by the standards PR. Production migration evidence is recorded below.

Each row is a migration item, not an architectural exception. Separate machines within a row remain separate lifecycles. Before closing a row, enumerate its concrete machine files and all replaced callers/setters, record the representation and version conversion, remove competing decisions, and link the passing tests and commit. Existing test files below are characterization anchors, **not proof that the proposed migration or missing regression tests already exist**.

Every durable item must prove atomic event/state/intent admission, identity conflicts, late/stale results, authority rechecks, commit-to-wake recovery, restoration and data migration. Every local item must prove scope ownership, late-result rejection, cancellation and joined cleanup where resources exist. Tests must distinguish a resumed attempt from a newly authorized attempt. Add failure-sensitive controls and browser tests where applicable. These common criteria apply to every row in addition to its specific invariants.

## Dependency order

1. **Foundation:** official integration, synchronous decisions, supported semantics, native handoff/wake proof, static rules and version contract (standards PR).
2. **Authority and high-risk ownership:** Access, agent archive/membership fences, Terminal atomic claimant/cleanup ownership, reply uncertainty and remote Stop obligations. These protect subsequent migrations; independent domains may be implemented separately.
3. **Coupled durable protocols:** Conversations root/input progression and run recovery; Communication/Coordination and Delegation; Workspace preparation; Routines, Webhooks and Apps admission. Preserve existing atomic admission transactions rather than layering a second queue.
4. **Other owned workflows:** Memory summaries and backup publication, Planning/Objects operation fences, model sign-in/credential rotation, MCP connection ownership, browser/execution and transport host lifetimes.
5. **Frontend lifecycles:** local flows may start once their own contract is proven. Conversation/draft recovery follows the relevant backend contracts; isolated UI/resource machines do not wait for unrelated backend migrations.
6. **Closeout:** rescan all source roots, resolve new candidates, verify exclusions, remove obsolete controls, run full required CI, and attach per-row evidence.

This order follows failure risk and dependency/authority coupling, not file size.
