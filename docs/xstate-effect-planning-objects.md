# Planning and Objects operation authority

B14 keeps plans, working objects, histories, root bindings, operation receipts and cancellation sentinels in their existing Pi documents. Official `@xstate/effect` machines decide application transitions synchronously within the existing native commit callback. Pi still owns document identity, transaction publication, serialization and rollback. There is no additional journal, scheduler, durable wake or execution engine.

## Contract and ownership

A plan is reported work and evidence, not permission to run a task. `planMachine` owns empty → open/completed, completion invalidation, continuation and absorbing cancellation. It reconstructs from the existing `Plan.state`; `complete` is a checked projection written with that state. Changed requirements or stale evidence reopen completed steps and prevent completed-plan authority from surviving invalidation. Evidence retrieval and comparison remain work and pure computation; step values do not submit, schedule or restart Pi tasks.

`planBindingMachine` owns each root's available/cancelled authority and its immutable logical-plan binding. Cancellation before any plan exists persists the existing empty-binding sentinel. A cancelled root refuses a later bind or replay. `planOperationMachine` owns pending/committed receipt decisions. Exact digest replay returns the original receipt without evaluating evidence or rewriting plan/history; different immutable input conflicts. Current-run authority and binding cancellation still take precedence over replay, while newer steering alone does not invalidate an already committed exact receipt.

`objectOperationMachine` owns open/applied/cancelled mutation decisions. A cancel that wins first leaves an absorbing sentinel; a commit that wins first retains its receipt and cancellation reports `applied: true`. An explicitly reapplied change needs a new operation identity. Checklist tasks, checked values, fields, object archival and offered-sequence projections remain plain user-authored data. They do not become execution states.

The former Plan completion/cancellation/replay reducers and Objects operation cancellation/replay reducers are removed. Storage adapters validate and materialize records; service functions perform work, final authority checks and atomic publication; machine transitions alone choose these durable lifecycle changes. The machines do not start actors or asynchronous effects inside their synchronous decision functions. Native callback execution and interruption remain the existing `nativeCommit`/Effect scope boundary.

## Versions and restoration

Public Plan and Checklist payload schemas remain version 1. Existing document kinds, keys, session scope, history addresses, operation IDs and digest inputs are unchanged. Pi's **internal document migration version** advances from 1 to 2 only for `plans.task`, `plans.turn`, `plans.operation` and `working-objects.operation`. Catalogs, plan history, checklist documents and object history retain their prior document versions.

Planning's version-2 document wrappers add `workflowVersion: 1`; existing serialized plan JSON, serialized receipt JSON, digest, plan binding and cancellation flag are retained. The machine reconstructs its state from those authoritative fields. Objects' version-2 operation record converts the old cancellation flag/receipt into its single open/applied/cancelled state while retaining digest and receipt. Its record also names schema/workflow and installed library/Pi compatibility versions. Those package compatibility fields are not a new Pi task implementation or a saved native task snapshot. No native Pi task definition/version changes in B14; the installed package versions and official integration remain pinned by the repository.

Native `migrate` functions accept only supported version-1 records. Strict legacy decoding refuses partially tagged or future controls instead of resetting them. Current workflow/version validation rejects unsupported persisted controls. A valid-shaped current wrapper with an unsupported workflow version returns `unavailable` with compatible-application-version guidance. Pi's typed-access guard rejects newer native document versions; the adapter recognizes the exact pinned SDK error for owned document kinds and returns the same guidance. It does not suggest that retrying the same update can repair an unsupported format. Compatible legacy values materialize without changing immutable history; a successful native commit persists the conversion atomically with its other changes. If validation or work fails, no subset of a multi-document migration commits. Read-only snapshot materialization does not imply that a migration was written.

## Races, receipts and cleanup

Planning rechecks source input revision and run authority after evidence work and before publication. Root cancellation observed during evidence or revalidation prevents a new completion from winning. A cancellation sentinel is durable before reconciliation, so a later continuation cannot exploit a reconciliation failure. Cancelled plans do not reopen when evidence changes. Revalidation that changes a completed plan adds one system history revision; an unchanged subsequent read adds none.

A caller can be interrupted after Pi has committed but before its acknowledgement arrives. Native settlement and owned cleanup are joined; interruption does not erase the committed plan/object or authorize another identity. Exact receipt recovery remains available under current authority. The tests also retain the existing distinction between a committed receipt and a currently cancelled root that forbids further use of that task.

Objects now rechecks write authority after its cancellation document reads and immediately before publishing the sentinel. This closes a proven race where authority changed during those reads. The cancel/commit result still comes from the single operation machine, and operation capacity is charged only for a new terminal fact.

The owned Planning reader close uses the repository's `orDieAll` conversion so a compound checked failure, defect and interruption survive cleanup. Ordinary unavailable storage remains a typed failure. Invalid stored payloads and synchronous callback defects remain fatal. Persisted Plan completion and operation digest/receipt consistency are schema checks at restoration, so their failures remain fatal even when a legacy migration throws through a native Promise. Public Plan schemas are unchanged. The wrapper validator returns Pi's original tracked document rather than a detached decoded copy, retaining native mutation tracking. Neither local interruption nor successful cleanup implies that a remote effect was undone.

## Evidence and limits

Focused suites include `planning.test.ts`, `planning-boundary.test.ts`, `planning-evidence.test.ts`, `planning-lifecycle.test.ts`, `working-objects.test.ts`, `objects-lifecycle.test.ts` and the existing native-operation/commit Cause tests. The new tests use real Pi document storage backed by Node SQLite, native transactions and cold Harness reopen. They cover migration preservation, rollback across attempted migrations, unknown versions, exact operation replay, cancellation before creation and after commit, completed-plan invalidation, authority loss during cancellation, immutable history and joined cleanup.

Failure-sensitive controls remove the committed-operation digest guard, completed-evidence reopening, cancelled-operation restoration and final cancellation authority check. Each causes the corresponding behavioral assertion to fail. Pre-fix probes also reproduce silent legacy workflow downgrading and lost compound reader-cleanup causes.

Independent review found that legacy completion/receipt corruption became an ordinary unavailable response, while future native versions received incorrect retry guidance. The final correction makes persisted completion and digest/receipt consistency schema failures, preserves fatal Cause through migration and HTTP, and gives unsupported native/current workflow versions compatible-version guidance. Partially tagged legacy records remain fatal. The public Plan schema, document identities, raw receipt/history payloads and cancellation sentinels are unchanged. The validator retains Pi's tracked document rather than returning a detached decoded copy.

The [retained owner regression before repair](evidence/xstate-effect/b14-2026-10-23/planning-regression-before.log.txt) has nine expected failed assertions; [the same suite after repair](evidence/xstate-effect/b14-2026-10-23/planning-regression-after.log.txt) passes all eighteen cases.
