# F12 routines, webhooks and skills UI

## Routines and webhooks

The browser owns scoped official `@xstate/effect` actors. `routines-ui.machine.ts` owns loading, four-second visible-page observation, command admission, acknowledgement, explicit retry, cancellation resolution and Stop uncertainty. `webhook-ui.machine.ts` owns settings load, configure-and-verify, exact retry and cancellation resolution. Effect owns native request/body settlement and scope cleanup. Routine contents, schedules, editor fields, selection and pure list merging remain data. The existing B11 backend remains authoritative for receipts, expected revisions, admission and native work.

One routine change snapshots its route, body (including its nested schedule), operation ID and expected revision at admission and retains those values until acknowledgement or cancellation plus a successful authoritative read. Later mutation of the caller’s draft object cannot alter Retry or Resolve. A duplicate SEND is never a retry: only the explicit RETRY event can re-use the retained command. Resolving first asks the backend to cancel that exact operation, then loads current state before releasing uncertainty. Stop retains the original run ID after an uncertain response; RETRY_STOP can only repeat that ID. No failure authorizes Run now or a new operation. Backend errors remain visible and uncertain work blocks unrelated mutation controls.

Each mounted agent owns disjoint actors. Switching agent aborts native requests and joins their eventual settlement; a late response cannot update the next owner or run its editor-close callback. The routine machine also captures a monotonically increasing view revision. A change acknowledged after A-to-B-to-A navigation updates the routine data but cannot close the current editor. Polling never retries a mutation: transient read failures retain the visible error and continue the existing four-second observation cadence until a successful read recovers. Hidden pages retain a timer but perform no polling read.

Webhook commands snapshot the original generated key and operation ID at admission, independently of the caller’s object. The key is revealed only after authoritative verification matches the configured revision and enabled state. A later revision hides it. Cancellation resolution reveals an already-applied key only when the current enabled revision is exactly the attempted expected revision plus one. Secrets remain in this owner’s memory and are never persisted by the UI. The endpoint, backend request contracts, key generation and copy affordances are unchanged.

Both owner adapters register their cleanup observer before creating actors, so actor/native cleanup joins before the outer scope reports late defects or a checked failure accompanied by interruption. The observer captures the raw Exit before recovery can replace it with the local cancellation reason. Fail, Die, original Interrupt identity and annotations remain represented; no cleanup filter drops interruption reasons. The shared native adapter also retains mixed late Causes without requiring an existing Die, while ordinary abort and pure interruption retain their existing behavior. Component unmount closes the owning scope and logs non-interruption failures. Remote mutation receipts retain their backend authority.

### Routines/webhooks evidence

The pre-change actual-Chromium probe held an Alpha save acknowledgement, changed to Beta, then released the old acknowledgement. It incorrectly called the editor-close callback once. The byte-unchanged probe now records zero callbacks and only Beta’s new read after the switch (`/private/tmp/f12-before-probe.log`, `/private/tmp/f12-after-probe.log`).

`tests/routines-ui-lifecycle.test.ts` drives the actual machines/owners through duplicate events, lost acknowledgements, exact retries, cancellation/read failure, retained Stop identity, A-to-B-to-A navigation, automatic recovery after four failed observations, malformed events, stale webhook configuration and full late native cleanup Causes. An independent unchanged probe exposed and now verifies repaired caller-object aliasing and Fail-plus-annotated-Interrupt cleanup without Die, for both actual native requests and direct uninterruptible Effect capabilities. The added regressions cover all three routine command shapes, nested schedules, webhook secrets, exact cancellation identities and original annotations. Existing routine/webhook tests are preserved. `tests/browser/routines-ui-lifecycle.spec.ts` bundles the production React hooks and actors in an isolated local harness, holding synthetic fetches across abort and acknowledgement boundaries. Desktop/mobile cases cover the same request and view identities. `F12_BREAK_VIEW_FENCE=1` changes only the bundled revision check; the unchanged navigation assertion must fail when the old completion closes the editor.

These local proofs use synthetic fetch responses and no live provider, webhook event or routine execution. They establish browser ownership and request identity, not remote exactly-once effects. The UI does not persist a pending command across reload; its existing pending-work/reload guard is the boundary. Parent-owned composed application gates cover full routing, layout and backend integration.

## Skills

The per-agent Skills actor owns library/selection observation and one immutable save, archive or select CAS command. Reload reads authoritative state without repeating a write. Explicit Retry same change retains the original ID, contents, source and expected revision. An editor/file/history machine fences completion by owner and generation; skill text and ordinary form fields remain React data.

The hosted-import machine captures the selected provider and catalogue revision, verifies the pinned preview identity and source, and emits a local draft only. Saving that draft remains a separate explicit user action. HTTP requests receive an AbortSignal; unabortable `File.text()` work remains joined to its owner. Scope cleanup preserves complete defect-bearing native Causes, including accompanying checked failure and interruption reasons. The existing 64 KB file input limit, 16,000 character limit and backend catalogue/source bounds remain unchanged. No new persistence, version migration or read retry budget is introduced.

`tests/skills-ui-lifecycle.test.ts` and the preserved domain tests cover the Skills actor/resource boundaries. `tests/browser/skills-lifecycle.mjs` drives the actual SkillsPanel on desktop and mobile through same-CAS retry, conflict reload/reapply, local file reading and held hosted-read closure. The original mounted agent-switch reproduction goes from stale publication to fenced completion. An isolated editor-generation control fails when the guard is removed: the late acknowledgement returns to the library instead of retaining the newer editor. Raw before/after, focused-test, browser and control evidence is in `/private/tmp/f12-skills-ui`. Synthetic local capabilities do not establish live hosted-provider delivery.
