# Coordination and child-group lifecycles

This B08 candidate gives addressed delivery, local child dispatch and detached child cleanup explicit owners. It also fixes a reproduced Stop race: native abort could acknowledge before a held addressed submission was admitted. Stop now revokes future admission, joins the existing dispatch owner, and only then acknowledges native cancellation.

## Ownership

The [message machine](../src/coordination/message.machine.ts) decides claim, expiry, accepted/failed/unconfirmed outcomes and restoration inside the existing `agent_messages` transaction. Delivery means recipient acceptance, not an answer. Main-conversation admission and message acknowledgement retain their shared SQLite transaction, current authority checks and exact attempt fence.

The [group machine](../src/delegation/group.machine.ts) and [child dispatch machine](../src/delegation/child-dispatch.machine.ts) keep group closure separate from child cleanup. One per-child owner joins initial submission, steering, addressed messages and Stop through native settlement. Detached groups remain open after an initial answer. `Delegations.deliverMessage` shares this owner and preserves the original message identity and attributed text.

Remote children use the [background task machine](../src/delegation/background-task.machine.ts), [scoped dispatch machine](../src/delegation/background-task-dispatch.machine.ts) and group-lifetime owner. Existing Pi documents, native request IDs, budget counters, route and provenance remain authoritative. B03 parent Stop policy is unchanged.

The [admission machine](../src/coordination/admission.machine.ts) prearms discovery before acceptance and checks the lease inside the acceptance transaction. Effect scopes join cleanup and preserve interruption and defect reasons. The [discovery machine](../src/coordination/discovery.machine.ts) retains an early empty scan; the [runner](../src/coordination/adapters/lifecycle.ts) uses the existing Lifecycle capability and pump identity with three bounded SDK attempts. Stale callbacks and hung replacements cannot steal a live owner or delete newer discovery. The local [runner machine](../src/coordination/runner.machine.ts) owns cold/restoring/ready activation, exact callback ownership, failed-owner SDK retry admission, wake coalescing and closed admission. Its invoked Effect joins concurrent restoration callers and returns the same restoration result; a failed restore becomes eligible only for another caller/SDK attempt. The capability owns the actor scope and native Promise handles, and Lifecycle capability disposal closes admission, joins accepted operations and then closes that scope. No runner state is persisted. Native callback identity is the original job object, including when a hung replacement has the same durable token.

Known family revocation is persisted before cleanup begins. The worker awaits `Delegations.revoke(turnId)`, which applies group `REVOKE` and active-child `STOP` atomically through the existing parent/group binding, including detached children whose parent has already completed. It creates no operation identity or retry budget and performs no native or scheduler work. Deadline and known-authority reconciliation share the same transition.

The production pump then performs cleanup with `allowDispatch:false`: it admits no new addressed messages, initial child work, steering or reports, and joins the existing native owner before acknowledging Stop. Unknown authority alone does not imply revocation. Repeated known revocation does not restart stopped children or renew exhausted/unconfirmed cleanup; expiry remains effective without renewed authority.

## Compatibility

[Migration 17](../migrations/agent/20261023130802_coordination_lifecycle/migration.sql) adds schema/workflow version 1, revision, phase and attempt identity to addressed messages. Existing accepted, delivered and failed rows retain their corresponding phase. Local Pi group records explicitly convert legacy JSON without changing IDs or counters. Remote BackgroundDocument version 2 accepts version 1 through explicit conversion and keeps schema 2/workflow 1; old stopped flags do not manufacture native acknowledgement. Future or invalid formats fail without resetting storage.

## Local runner coverage completion

This bounded follow-up replaces the adapter's `restored`, `active` and `wakeRequested` decisions with the official local machine. The native operation set and disposal Promise are resource handles, not alternate admission state. The existing Lifecycle pump identity, singleflight policy, ten-minute hung threshold, three SDK attempts, discovery format, domain restoration and message records are unchanged. There is no new scheduler, business retry or journal.

The unchanged recovery acceptance suite passes all eight cases. Together with the new runner cases and existing discovery/held-dispatch tests, 23 focused tests pass. New held barriers prove one concurrent restoration, explicit retry after failure, wake coalescing, same-object overlap refusal, exact failed-owner retention, no producer after held-restore disposal, no storage access after disposal, and joined terminal cleanup. A native step rejection containing checked failure, annotated defect and Interrupt(88235) preserves every reason both to its callback and to the waiting disposer. Runtime schema validation rejects malformed callback observations.

An isolated temporary-copy control removes only the failed-owner reference guards. The unchanged ownership test then fails because a same-token replacement invokes a second step. This is sensitivity evidence for the local callback fence. These added checks run the real official Effect actor and native JavaScript Promise barriers with a fake Lifecycle queue; they do not constitute a new workerd/SQLite/Pi or real-provider run. Earlier native evidence above remains historical. Parent-owned integrated and native gates remain separate.

Fresh independent review found that the restoration Promise boundary could squash a structured Cause before the native bridge saw it, and that the Deferred reply boundary could squash it again. Restoration now materializes its Exit inside the host runtime and explicitly throws its full Cause to the callback. A held annotated Fail+Die+Interrupt(94001) regression checks all three reasons and annotations at both callback and disposer boundaries. The unchanged independent probe passes after this narrow repair.

The composed native gate subsequently reproduced a startup-context hang: the constructor-created actor invoked restoration outside Lifecycle's reentrant startup context. The runner now constructs its scoped actor lazily in the first caller's context and runs restoration directly as an Effect. This removes the unnecessary host Promise round trip while retaining the machine's complete Exit and explicit callback Cause. The new context regression fails before and passes after; the unchanged independent eight-case probe still passes. [Host census evidence](xstate-effect-host-census.md) records the integration correction separately from the original freeze.

### Joined host shutdown correction

Native PersonalAgent composition also showed ActorServices closing its runtime before Lifecycle reached CoordinationRunner disposal. A held native callback could still need those resources. ActorServices now closes Coordination admission and joins accepted work concurrently with provider, credential and upstream shutdown, before runtime/storage release. The native regression uses the real Lifecycle and actor runtime, holds a synthetic step, then reads the actual configuration through that runtime before it settles. It fails against the preceding host order and passes after the correction. The original independent runner Cause probe remains scoped to the runner, not this host-ordering repair.
